1. これは何か

診療ダッシュボード本体（generate_html.py が作るWeb版）とは別立ての、 院内配布・印刷用のPDFレポートを生成する仕組みです。月1〜2回、部門会議や ミーティングでの配布を想定しています。

在院・新入院・全身麻酔手術・粗利・週末の入退院バランスを、部門ごと（診療科／病棟）に A4 1枚へまとめ、あわせて病院全体のサマリも自動生成します。

2. 生成される3つのPDF

ファイル内容ページ数の目安
診療科版_{基準日}.pdf 診療科ごとに1ページ（全診療科を連結・一括印刷用） 約20ページ
病棟版_{基準日}.pdf 病棟ごとに1ページ（全病棟を連結・一括印刷用） 約17ページ
病院全体サマリ_{基準日}.pdf 1ページ目=KPI＋グラフ／2ページ目=病棟別実績表／3ページ目=診療科別実績表 3ページ

出力先は dept_reports/{基準日}/ です。--split を付けると、 部門ごとの個別PDF（{基準日}/診療科/{診療科名}.pdf など）に分割されます。

3. 実行方法

3.0 関連する.shファイル（このリポジトリ全体の位置づけ）

リポジトリ直下には3つのシェルスクリプトがあり、それぞれ役割が異なります。 このマニュアルの対象は build_reports.sh だけです。他の2つは 診療ダッシュボード本体（Web版）の運用スクリプトで、部門別レポートPDFの生成には 関与しません。

ファイル役割実行タイミング
pull.sh 作業開始時に GitHub から最新コードを取得し、requirements.txtの 変更をライブラリへ同期する 作業を始める前に手動実行
deploy.sh 診療ダッシュボード本体（Web版）をビルド（generate_html.py・ 医業収支推計・自己完結HTMLを生成）し、コミット→GitHub Pagesへプッシュする。 git log に残る「Dashboard update: 日時 [M5-Pro]」の コミットはこのスクリプトによるもの（定期実行の自動化あり） 作業終了時、または定期実行
build_reports.shこのマニュアルの対象 部門別レポートPDF（診療科版／病棟版／病院全体サマリ）だけを生成する。 deploy.shとは独立しており、手動でダブルクリック実行する 運用（月1〜2回） 部門会議・配布の前に手動実行
build_reports.shはdeploy.shの自動コミット/プッシュには 含まれません。PDF生成のみを行い、git へのコミットは行いません （dept_reports/はローカル出力専用）。

ダブルクリック実行（AppleScript/Automator）

build_reports.sh をダブルクリック、または Automator から呼び出します。 oMLX（一手のAI要約）が未起動なら自動で起動を試みます。

コマンドライン（make）

# 既定（軸ごと連結＋AI一手）
make reports

# 一手を定型文のみ（oMLX不要・高速）
make reports AI=off

# 部門ごとの個別PDFに分割
make reports SPLIT=on

# 基準日を指定
make reports DATE=2026-05-31

直接実行（オプション詳細）

python scripts/build_dept_reports.py [オプション]
オプション説明
--data-dir DIRデータディレクトリ（既定: data）
--output-dir DIR出力先（既定: dept_reports）
--base-date YYYY-MM-DD基準日を指定（既定: データ最終日）
--axes dept,ward診療科版・病棟版のどちらか/両方（既定: 両方）
--no-ai「この期間の一手」をAI生成せず定型文のみにする
--only 診療科名特定の1部門だけ生成（確認・動作確認用）
--limit N先頭N件のみ生成（確認用）
--split部門ごとの個別PDFに分割
--keep-htmlPDF化前の中間HTMLも出力先に残す
--quiet / -q進捗ログを抑制
Chromeが必要です：PDF化には headless Chrome（または Chromium / Edge）の --print-to-pdf を使用します。見つからない場合は HTML のみ出力されます。

4. 各ページの見方

4.1 KPIカード

診療科・病棟は4枚、病院全体サマリは5枚（在院患者数・新入院・全身麻酔手術・粗利・ 週末在院維持率NEW）。 カード左の色帯・実績値の色が達成状況を表します。

色意味
緑（達成）目標達成（達成率100%以上）
橙（接近）目標に接近（90〜100%未満）
赤（未達）目標未達（90%未満）
グレー（—）目標未設定、または ※色評価の対象外（業務実態が一般部門と異なる科・病棟）

週末在院維持率＝土日平均在院 ÷ 平日平均在院。目標93%。病院全体サマリのKPIカードと、 病棟別／診療科別の実績表に表示されます。

4.2 グラフ A〜E（優先順位で配置）

部門の種別ごとに、優先度の高い順で配置が変わります（優先1位=全幅ヒーロー表示）。

種別優先順
外科系診療科全麻手術 → 粗利 → 曜日プロファイル → 新入院 → 在院
内科系診療科在院 → 粗利 → 新入院 → 曜日プロファイル
病棟病床利用率 → 新入院 → 曜日プロファイル
  • 実線＝当年実績、グレー線＝前年同期、破線＝目標（病棟は目標利用率）
  • 網掛け（緑/橙）は目標超/目標割の区間を表す。線の色そのものは成績ではない
  • 粗利チャートは確報の末尾に、点線＋中空マーカーで「当月見込み」を接続 NEW（実績が確定するのは翌月20日ごろのため、 直近月は診療実績ベースの推計値を暫定表示）

4.3 病院全体サマリ 2・3ページ目（実績表）

病棟別・診療科別の実績を一覧表で表示します。診療科別テーブルの右端は 「粗利予測達成率」＝当月見込み粗利 ÷ 目標です。

ICU・HCUも通常どおり色評価の対象ですNEW（以前は 業務実態の違いを理由に評価対象外＝グレー表示でしたが、目標・実績が揃っており 評価可能なため、2026-07-01 に対象へ含めました）。
※眼科は業務プロファイルが未整備のため、引き続き色評価の対象外です。

5. 「この期間の一手」の仕組み

各部門ページの右下（またはグラフの空きコマ）に、AIまたは定型文による 「今週/この期間の一手」を1件表示します。 2026-07-01 リニューアル

5.1 3トピックから自動選択

以前は「週末在院の平準化（病床管理）」一辺倒でしたが、現在は下記3トピックのうち 目標未達が最も大きいものを自動選択します。

トピック対象レバー（提案の方向性）
病床平準化診療科・病棟金曜集中の退院を平日へ分散／週末入院で空床補充
新入院診療科・病棟地域医療連携の強化／予定入院枠の調整
全麻手術外科系診療科のみ手術枠の稼働確認／執刀医との症例調整

目立った不足が無い部門は、従来どおり「病床平準化」を既定（在院が良好なら現状維持の 定型文）にします。

5.2 救命救急センター系病棟（4階A・4階C）は専用文言

4階A病棟・4階C病棟は緊急入院・院内転棟が中心で、他病棟のような 「予定入院の曜日調整」「地域医療連携（紹介元）への働きかけ」という業務前提が 成り立ちません。この2病棟だけ、トピックの選び方（平準化 or 新入院、どちらの 不足が大きいか）は共通ロジックのまま、文言だけ専用に差し替えています （転棟・転出判断の迅速化、週末含めた受け入れ体制・当直の維持、など）。

6. AI（一手の自動生成）について

要約LLMには oMLX（OpenAI互換ローカルAPI・Llama-3.1-Swallow-8B）を使用します。 oMLXが未起動、またはAPI呼び出しに失敗した場合は、自動的に定型文へフォールバック します（レポート生成自体は止まりません）。

ハルシネーション対策

LLMに数値の計算や事実の創作をさせないよう、次の対策を二重に行っています。

  • プロンプト設計：LLMには定性語（例:「目標を明確に下回っている」）だけを事実として渡し、 具体的な数値・原因・傾向は一切与えない。数値の再引用・新しい理由づけを禁止する指示を明記。
  • 機械的ガード（プロンプト指示だけに頼らない）：生成された本文・アクションに
    • 半角・全角数字が含まれる
    • 与えていない傾向・原因を示す語（「傾向」「稼働率」「逼迫」等）が含まれる
    • 危険な提案（在院日数の延長＝「延伸」「早期退院」等）が含まれる
    • 異常に長い（暴走出力）
    のいずれかに該当する場合は棄却して定型文にフォールバックします。
このガードは完全ではありません（未知の言い回しでの創作までは検知できません）。 それでも数値の捏造や、与えていない傾向・原因の主張は高い確率で検知して棄却します。

7. トラブルシューティング

症状対処
PDFが生成されずHTMLだけ出るGoogle Chrome / Chromium / Edge のいずれかをインストールしてください。
「この期間の一手」が定型文ばかりになるoMLXが起動しているか確認（build_reports.shは自動起動を試みます）。ハルシネーション棄却が多いだけの場合もあり、異常ではありません。
生成が遅いAI一手はユニットごとに逐次LLM呼び出しを行うため、部門数が多いと数分かかります。急ぐ場合は --no-ai を使用してください。
特定の1部門だけ確認したい--only 診療科名 で該当部門のみ・高速に個別出力できます（病院全体サマリは省略されます）。
