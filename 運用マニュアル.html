3. 日次：deploy.sh

日次

作業終了時に1回。ビルド・コミット・pushをまとめて行い、公開ダッシュボードを最新化します。

$ ./deploy.sh

内部で起きていること

  1. oMLX（AI一手生成用ローカルLLM）の起動確認。未起動なら自動起動を試みる
    失敗しても止まらない。以降のAI生成が定型文にフォールバックするだけ
  2. generate_html.py でHTML生成
    ここで失敗すると即エラーダイアログで停止する（唯一の致命ポイント）
  3. 医業収支 推計レポート（pl_projection.html）を生成
    失敗してもデプロイは継続。非公開・院内限定のため
  4. Comedix配布用の自己完結HTML（部門・ポータル）を再出力
    同上、失敗してもデプロイは継続
  5. git add（対象は固定リスト：portal.html detail.html dept.html app/templates/ app/lib/ など）
  6. 差分がなければ「変更なし。スキップ。」で終了。あればコミット
  7. push。拒否された場合は git pull --rebase を挟んで1回だけ自動リトライ
失敗したら：macOS通知ダイアログが出ます。詳細は /tmp/dashboard_deploy.log を確認してください。rebase も失敗した場合はコンフリクトの可能性があるので、手動で git pull --rebase origin main してから再実行します。
scripts/ や tests/ を編集した日は要注意です。deploy.sh の git add はファイル名を明示リストで指定しており、scripts/ と tests/ は含まれていません。新規追加・編集した場合は忘れず手動で git add してください。

4. 週次：部門別レポート（build_reports.sh）

週次

診療科版・病棟版・病院全体サマリの3PDFを、AIコメント（今週の一手）付きで生成します。既定は「レビュー運用」— 生成後にブラウザが自動で開き、その場でコメントを直せます。

$ ./build_reports.sh

レビュー運用の流れ

  1. 生成完了後、レビュー画面（レビュー_{基準日}.html）がブラウザで自動的に開く
  2. AIが書いた「今週の一手」が不自然な科があれば、画面上で直接編集
  3. 「保存」→ dept_reports/overrides.md に書き込まれる
  4. 「PDF再作成」ボタンで差し替え反映（生成キャッシュが効くため数秒）
  5. 画面内の「できあがりPDF」リンクから開いて印刷

「すべてAI文に戻す」を押したとき：これは画面上の下書きを戻すだけで、overrides.md にはまだ書き込まれていません。必ず「保存」してから「PDF再作成」を押してください（保存を挟まないと戻したことが反映されず、ボタンが効かないように見えます）。また「PDF再作成」は ./build_reports.sh で開いたレビュー画面でのみ有効です。ファイルとして直接開いた場合や「サーバ終了」と表示された場合は、ターミナルで ./build_reports.sh を再実行すれば反映されます。

レビューサーバは無操作120分で自動終了します。手動で止めたい場合はターミナルで Ctrl+C。

オプション効果
--no-reviewレビュー画面を開かず生成のみで終了（従来運用）
--no-ai一手をAI生成せず定型文のみ（oMLX不要・高速）
--fast意味整合チェック（judge）を省略し初回生成を高速化
--no-review --split軸ごと連結せず部門ごとの個別PDFに分割
--base-date YYYY-MM-DD基準日を指定して過去日で生成
--port=8770レビューサーバのポートを明示指定（既定8768・使用中なら自動でずれる）

overrides.md（一手の手動差し替え）

レビュー画面の保存先。[診療科:名前] [病棟:名前] [病院全体:病院全体] のブロックに body:（現状の説明）・action:（次の一手）を書きます。expires: を過ぎたブロックは自動的に無視されるので、消し忘れても実害はありません。テキストエディタで直接編集しても構いません。

dept_reports/overrides.md（抜粋）[診療科:一般消化器外科] expires:2026-07-29 body: 週末の在院がやや落ち込み、直近4週で悪化傾向にあります。 action: 手術件数を増やして平均を上げていきましょう。加えて金曜に集中する 退院の一部を日〜月曜へ分散し、週末の在院数を安定させてください。

コメントの質を設定・改善する

AIの「今週の一手」は次の3つで底上げできます。いずれも数値・事実はデータ由来のまま、言い回しと打ち手の質だけを上げる仕組みです（AIに事実を創作させない設計）。

やることファイル効果
今期の経営方針を書く data/management_policy.yaml
（config/management_policy.example.yaml をコピーして編集）		 「今期は手術件数を最優先」等の方針を書くと、AIの見出し・打ち手の優先順位がそれに揃う。院内非公開（data/ は非公開・GitHubに載らない）
診療科の打ち手（レバー）を定義 config/evaluation_rules.yaml の各群 levers: 「手術枠の再配分」等その群が実際に動かせる手を列挙すると、AIの action が決まり文句でなくその中から具体化される
人の添削を蓄積・活用 scripts/mine_report_edits.py レビューで直した一手は自動で記録される。python scripts/mine_report_edits.py で「AI原文→人の最終文」の突き合わせ（_state/edits_digest.md）が出る。よく直す打ち手はレバーへ昇格すると次から精度が上がる

出力ファイル

ファイル内容
診療科版_{基準日}.pdf診療科ごとの実績（1部門1頁・一括印刷用に連結済み）
病棟版_{基準日}.pdf病棟ごとの実績（同上）

5. 随時：院内配信（Comedix・実績まとめ・ダイジェスト）

週次目安

Comedix「お知らせ・回覧板」や資料室へ配信する3系統。目的が近いので使い分けだけ押さえれば十分です。

make comedix

今週の一手＋KPI3＋在院トレンドを1枚のPNG画像にして、Comedix資料室の固定文書へ上書き。お知らせ本文からは画像として貼るだけ。

make comedix-html

同じ内容をインラインstyleのみのHTML断片で出力。お知らせのHTMLソースへ直接貼付でき、画像アップロード不要。病棟・診療科テーブルまで含む詳細版。

$ make comedix REFRESH=1 # 今週の一手.md を自動下書きへ書き戻す

今週の一手.md の編集

本文をそのまま直接編集して make comedix（または comedix-html）を再実行すれば反映されます。自動下書きに戻したいときは REFRESH=1。維持率・伸びしろの数字部分は常にデータから自動計算されるので、この文面では触れません。

output/comedix/今週の一手.md土日の在院ディップを埋める この流れで土曜の退院を月曜へ。週末の退院準備の前倒しを継続してください （総退院数・在院は維持）

make report-hospital

全病院 実績まとめPDF（A4 4頁）。KPI3・12週トレンド3枚（前年同期線つき）・病棟別/診療科別テーブル。週次〜月次で配布向け。

make digest / digest-fast

掲示用A4＋メール貼付テキストの週次ダイジェスト。digest-fast はAI要約なしで確定差分の箇条書きのみ（高速・oMLX不要）。

6. 月次：粗利ダッシュボード（配信用HTML）

月次

「人件費10万円あたり粗利」ダッシュボード（粗利ダッシュボード_配信用.html）を公式年度Excelから自動生成します。従来のブラウザ内手動取込→手動エクスポートは廃止し、公式Excelを置いて1コマンド実行するだけの運用になりました。新版はパスワード無し（開くだけで全タブ表示）。院内配布用の機密ファイルで、GitHub Pages には公開されません（.gitignore 対象）。

月次手順

  1. 公式の年度別Excel（☆入外合算粗利YYYY（幹部抜き）.xlsx）の最新版を data/profit_xlsx/ に上書き配置する
    過去年度のファイルは置いたままでよい
  2. ハブの「Dashboard 生成・公開」パネル →「▶ 粗利ダッシュボード生成（ローカルのみ・公開しない）」を押す
    完了時に取込サマリが表示される。CLIから実行する場合は python3 scripts/build_gross_profit_dist.py
  3. 出力を確認する
    粗利ダッシュボード_配信用.html（上書き）と output/粗利ダッシュボード_配信用_YYYYMMDD.html（日付控え）
  4. ブラウザで開いて内容を確認し、院内配布する

鮮度ガード（取込スキップの仕組み）

内容変更なし（取込済み） — 前回取り込んだファイルと内容が同一（ハッシュ一致）なら取込をスキップします（無駄な再取込を避けるだけで実害なし）。

ストアより古い断面（日付）のためスキップ — 置いたファイルの更新日時がストアの最新断面より古い場合はスキップします。古い版で最新データを潰さないための仕様です。改訂版を取り込みたいときは、最新のファイルを置き直せば（内容が変わっている限り）取り込まれます。

支援系5科の扱い

メンタルケア科・リハビリテーション科・緩和ケア内科・放射線診断科・麻酔科は粗利指標の対象外です（粗利・人件費とも全体値から除外）。「支援系科（人件費）」タブに人件費推移を別掲します。全身麻酔手術件数・リハ単位数などの実績評価軸が決まるまでの暫定措置で、臨床腫瘍科は従来通り粗利評価の対象です。

対象科を変更する場合：テンプレート data/gross_profit/template.html 内の LABOR_EVAL 定数1箇所を編集します。編集前に template_backup_日付.html を作成してください。
同ファイルには科名リストがもう1つ（REPORT_EXCLUDE）ありますが、これを使う buildReportHtml() は導線となる btnReport 要素が存在せず動作しません（未使用コード）。編集不要です。

患者数月報（任意）

data/patient_monthly/ に月報Excel（「入力及び月設定」シート形式）または抽出CSVを置くと、増員タブの「必要な入院患者数増」表示が更新されます。置かなければ従来のデータが維持されます。

8. トラブルシューティング

症状原因・対処
oMLXが起動しない／モデル未取得 AI一手・週次まとめの生成がスキップされ定型文にフォールバックするだけで、ビルド自体は止まりません。手動起動は open -a oMLX。
deploy.sh でpushが拒否される 自動で git pull --rebase を挟んで1回だけリトライします。それでも失敗する場合はコンフリクトの可能性があるため、手動で git pull --rebase origin main 後に再実行してください。
レビューサーバが起動しない／ポート使用中 既定ポート8768が使用中なら自動で空きポートへずらします。--port を明示指定した場合のみ、衝突するとエラーで停止します。
「変更なし。スキップ。」と出る 前回ビルドから data/ の内容が変わっていません。新しいデータファイルを追加してから再実行してください。
部門別レポートPDFだけ科別の粗利見込みが抜ける 公開ダッシュボード（make build）と部門別レポート（make reports）は粗利推計の呼び出し経路が異なります。前者が通っても後者が壊れることがあるため、粗利推計まわりを変更した週は make reports まで通して確認してください。
粗利カードで実績が目標を上回っているのに「接近」と表示される 達成率は常に「月次目標(補正)」（営業日/暦日で補正した目標）基準です。営業日・暦日の多い月は補正目標が名目の月次目標より上振れするため、名目目標を上回っていても補正目標には届かず「接近」のままになることがあります。カードの目標欄は補正目標を表示し、脚注に名目目標を併記しています（診療科ランキング・粗利ドリル・dept.htmlの粗利カードも同じ基準）。
「先に extract_gross_profit_seed.py を実行してください」と出る data/gross_profit/ の seed_store.json か template.html が消えています。バックアップから復旧するか、旧パスワード版HTMLがあれば python3 scripts/extract_gross_profit_seed.py --password <管理者パスワード> --html <旧パスワード版HTMLのパス> で再抽出してください（--html 省略時は現行のパスワード無し配信用HTMLを見に行ってしまうため、旧パスワード版のパスを明示してください。パスワードは口頭伝達・ファイルには書かない）。
新しい月のデータが反映されない 取込サマリを確認してください。「ストアより古い断面（日付）のためスキップ」なら置いたファイルが古いので最新版を入手して置き直します。「内容変更なし（取込済み）」なら既に取込済みです（HTML側の表示月を確認）。
ハブの「粗利ダッシュボード生成」ボタンがエラーになる CLIで python3 scripts/build_gross_profit_dist.py を実行し、エラーメッセージを確認してください。orchestrator 再起動直後は数秒待って再実行します。
粗利ダッシュボードの数値の妥当性を確認したい python3 scripts/verify_gross_profit_golden.py を実行します（値の衝突のみFAIL・改訂差は情報表示）。
粗利ダッシュボードの全体指標が以前の配布版より大きく見える 2026-08-14 の基準変更（支援系5科の対称除外）によるもので不具合ではありません（FY2025で約53.1万→60.8万円/10万）。
粗利ダッシュボードの増員タブの必要患者数が出ない／古い data/patient_monthly/ に最新の月報を配置してください。
